# UAG advertising monetisation matrix — 14 September 2026

## Actual implementation and changes

Source audit: `lib/main.dart`, all feature screen Dart files, `uag_ad_service.dart`, `uag_ad_policy.dart`, `uag_ad_runtime_settings.dart`, `uag_admob_config.dart`, `arc_raiders_screen_shell.dart`, and entitlement service. This is a static inventory, not device impression verification.

Canonical effective entitlement supplies advertising policy: Free allows banner/interstitial/app-open/rewarded; Essential allows bottom banners only; Premium disables every format. These tier booleans and subscription prices are unchanged. The runtime previously began with Free policy before entitlement resolution; it now fails closed until entitlement arrives, including account switches.

Android is the only initialized SDK platform; web and iOS return without initializing. Existing google_mobile_ads supports rewarded, but there is no rewarded loader, unit configuration, presentation, verified grant or reward ledger in this app. Tier eligibility is not implemented availability. Removed three unimplemented paid-feature reward descriptions from Free policy. No reward grants or entitlement changes were introduced.

Existing defaults: test inventory, ads/banner/interstitial/app-open enabled; interstitial every 3 transitions with 120-second cooldown; app-open after 3 sessions with 15-minute foreground cooldown. Remote app_config/ads may differ; production values were not fetched or changed. The existing consent controller is a development placeholder and is not connected to service eligibility; release checklist prose is not an enforced gate. Production inventory must remain off until this is integrated and verified.

## Central placement implementation

`UagAdPlacementPolicy` now supplies an exact passive-route banner allowlist and stable placement identifiers. Existing banner consumers inherit it through the service. Unknown/unnamed routes, dialogs, auth, profile editing/setup, checkout, contracts/evidence, administration, reset and action flows fail closed. Routes with nested trading tabs are deliberately excluded because the top-level route cannot distinguish browsing from create/offer/session actions. No page migration or new banner density was introduced.

Automatic interstitial navigation and app-resume placements are now denied at the placement layer. Existing SDK integration/settings remain for future explicit reviewed natural-completion triggers; turning on the remote switch alone cannot bypass placement restrictions. This is an intentional traffic reduction to avoid interrupting unfinished work. Do not restore full-screen ads using only a navigation count. Candidate later experiment: after a user explicitly finishes and leaves a passive browsing session, at most 1 per session and 3 per day with >=10 minutes separation, never on Back, deep link, first paint or resume. This proposed cap is not implemented.

`UagRewardedAdPolicy` is a disabled pure eligibility foundation: Free only, signed in, explicit request, consent, server readiness, three verified completions/day, 20-minute minimum interval. It rejects invalid counts and future completion timestamps. It cannot grant anything and is not wired to SDK/UI. Server enforcement remains required.

## Known placement gaps and next implementation

- Existing profile/setup and contract screens request banner space in source, but central policy now denies it. Source presence must not be mistaken for permission.
- Tracker/blueprint banner slots remain; underlying grid, persistence and ownership logic were untouched.
- Some recommended passive routes currently disable their shell banner. They remain eligible but no new slot was added; verify layout and add a single shared bottom slot in a later focused change.
- Anonymous navigation is intentionally ad-free until it has a reviewed placement identity. This includes many secondary detail screens; do not infer safe eligibility from the parent.
- Rewarded consent, server transaction ledger, replay protection, cross-device cap enforcement, expiry, data deletion and delivery reconciliation remain unimplemented. A client boolean/counter is not fraud prevention.
- Tests added: `test/uag_ad_placement_policy_test.dart`, `test/uag_rewarded_ad_policy_test.dart`. Primary agent owns execution and records outcomes in the final handoff.

The pre-existing consent gap identified above is now contained by `UagAdPlacementPolicy.permitsAdRequests` and the live ad service: a release build cannot initialise the ad SDK or request a banner/full-screen ad unless the existing consent controller reports both a completed flow and permission to request ads. Debug/internal builds retain test inventory. The current controller has no production completion implementation, so release advertising intentionally remains unavailable until real UMP integration is supplied and tested. This is a request gate, not a claim that consent collection is implemented. No ad unit IDs, remote settings, prices or entitlement calculations changed.

Full-screen placement remains deliberately unavailable pending a reviewed natural-completion trigger. This reduces automatic inventory; it is not a completed ad-revenue rollout. A future route-stack observer test should cover non-top replacement/removal before widening coverage. New tests cover all four consent flag combinations for release and debug request policy.
